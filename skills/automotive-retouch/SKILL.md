# 汽车商业精修

把实拍当作结构依据，以局部清理、柔和光影和环境整理提升质感。将生成结果视为需要核对的候选图；提示词中的“锁定”不等于像素保护。

## 先建立这张照片的编辑边界

读取原片，辨认主车、陪体、前景虚化、遮挡关系和真实光源方向。保留用户刻意安排的茶叶、枝叶等前景，不因它们模糊就清除。区分主体双车构图与无关背景车辆；不能把所有其他车辆自动删掉。

按实际需要选参考，标明每张角色：原片、同车型的轮毂/灯组/标识细节、光影风格。参考要真正传入编辑工具或挂到画布节点，不能只在提示词中写“参考”。车头徽标不能移植到车尾，其他车型的轮毂不能当作身份依据；光影参考不能改变车型或搬入参考场景。

优先保护车身轮廓、透视、轴距、零件数量、门缝、轮毂辐条、中心标识、灯组形状与位置。允许编辑的光线、漆面污点、杂物、路面和天空由当前要求决定。移除车内人物是用户指定时的局部例外，保留玻璃、座椅和方向盘结构。

## 选择能保住主体的方式

- 用户指定 Image 或即梦时遵循选择；否则使用当前宿主实际可用的图片编辑能力。此 Skill 不包含模型，不自行获取密钥或替换服务。
- 若工具支持蒙版、分层或局部编辑，优先限制生成范围。结构需严格一致时，保留原车区域、对车身做非生成式光影调整，环境在独立区域处理；需要专业分层编辑器才能落实的操作不得宣称已实现。
- 全图图生图能探索整体质感，但仍可能重绘细节。对必须保持原件的任务，不能把这类结果称为已锁定或最终商业交付。
- 调用即梦前按已安装 CLI 的 help/schema 核对命令、登录和模型能力；不猜 flags、不打包他人的 CLI 或内部 Skill。费用、免费额度和输出上限按当前服务与账号核实，不承诺“2K 永久免费”。

## 执行与检查

1. 批处理先清点输入，只纳入授权范围；输出、参考、工作记录目录不要再次作为原图。保留原件，默认另存。继续已有批次时检查源文件哈希与结果是否匹配。
2. 写明保留项、清理项、光影目标、参考角色和输出要求。可按 [提示词模板](references/prompts.md) 组织。除非用户已要求统一风格，先按单张的曝光、场景和景深判断。
3. 保留自然反射与接地阴影，用宽而平滑的高光展示车身曲面。洁净漆面不等于抹掉金属纹理；通透不等于清除远山雾气；柔光不等于取消方向与明暗层次。
4. 检查清理对象及其投影/倒影，尤其车内、帐篷旁、窗户反射、电线末端。只清除用户指定的设施与干扰，赛道锥桶、轮胎痕或安全设施是否保留取决于画面目的。
5. 等任务实际完成、下载并逐张查看；提交成功不等于修图完成。核对标识文字、灯组、轮毂、边缘与遮挡，记录 `待核对`、`可作风格预览` 或 `已人工验收`。不能仅凭接口成功或文件存在判断合格。
6. 若关键结构变形，针对失败区域修正；连续两次未改善时回到原片并换用局部/分层方法，或如实报告能力限制，避免无限付费重试。
7. 读取成图实际宽高和格式；长边约 1536 的图不能标为 2K，放大为 4K 也不代表恢复真实细节。高分辨率交付要求见 [验收要点](references/quality.md)。

## 批次记录与展示

可用 `scripts/project.py inventory` 生成清单，`audit` 检查文件和真实尺寸，`compare` 制作有字幕、不裁切内容的前后对照或三版竖屏。脚本只做清点、检查和排版，不生成精修图；不代表视觉验收。

记录原片、实际工具、参考角色、提示词、任务 ID（如有）、状态、输出路径与尺寸，便于恢复。凭据、授权链接不要写入公开记录。

对比必须使用同一原片和实际对应版本，缺少任何一版就跳过该组，不能用另一引擎结果冒充。排版画布的分辨率要与照片本身的分辨率区分。公开展示前遵守用户的选片限制，清除 EXIF/GPS，不把原图目录、日志或未授权照片整体上传。

交付时说明保存位置、实际尺寸、完成项与未解决的结构问题。发布照片或仓库需有相应授权；修图请求本身不等于公开上传授权。
